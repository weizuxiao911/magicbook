# 消息总线服务设计:统一 `/global/event` SSE 广播

## 1. 设计说明

### 1.1 整体设计

**问题**: numas 客户端里多个功能面各自直连 opencode 的 SSE, 造成连接冗余与目录路由隐患:

- `extensions/ask/AskService.ts` 自建 `EventSource('/api/event')` (**既不带 header 也不带 `?directory=`**, 在非启动目录工作区收不到事件, 见 [提问命令设计](./提问命令-Ask无头通道设计与测试用例.md))
- `extensions/chat/webview/Chat.tsx` 自建 `EventSource('/global/event')` + 异步迭代器 + 3s 轮询重连
- `service/ports/ports.service.ts` 自建 `EventSource('/global/event')`, 只过滤 `ports.*`
- `service/filesystem/provider.ts` 的 fs watcher 用 `/api/fs/watch` (per-location, 相对路径 + 200ms 防抖) —— **语义不同, 不并入**

三条会话/端口类 SSE 同构重复, 且 ask 那条有 workspace 路由 bug。

**方案**: 在 service 层新增**框架无关单例消息总线** `sumi/src/service/event/eventBus.ts`. 它是**全客户端唯一**对接 opencode `/global/event` SSE 的地方: 连一条 EventSource → 归一化每一帧 → 用进程内回调广播给所有订阅者 (拓展). 拓展不再 `new EventSource`, 只订阅总线事件。

数据流:

```
opencode -sse-> service (eventBus) -event-> extensions
```

**为什么统一到 `/global/event` 而不是 `/api/event`**:
- `/global/event` 是**全局总线** (服务端 `handlers/global.ts` 直接桥接进程内 `GlobalBus`), **不经过 workspace 路由**, 一条连接即可收到所有 instance 的会话事件 + `directory:"global"` 的端口事件. 客户端按 `properties.sessionID` / `payload.type` / 信封 `directory` 自行过滤.
- `/api/event` 是 per-instance 流, 挂在 `WorkspaceRoutingMiddleware` 之后, 必须带 `x-opencode-directory` header 或 `?directory=` query, 且服务端按 instance 目录过滤; EventSource 无法发 header (铁律 8), ask 正是漏了 query 才失效. 且 `ports.*` 这类 `directory:"global"` 事件不在 per-instance 流里, 无法一条覆盖。
- chat 旧注释称 "V1 `message.part.delta` 只通过 V1 通道广播" 是**过时结论**: `MessageV2.Event.PartDelta` 即 `SessionV1.Event.PartDelta` 别名 (`session/message-v2.ts:59`), 会话所有事件都经 `EventV2Bridge` 广播到 GlobalBus, `/global/event` 能收到流式增量。

**核心要点**:
- **一条 SSE**: 整个客户端只有一条 `EventSource('/global/event')`, 引用计数 (首个订阅者开, 0 订阅者关), 浏览器自动重连。
- **框架无关**: 纯模块单例 (**不进 DI**), DI service (ports) / 命令式纯函数 (ask) / React 组件 (chat) 都能直接 import 订阅。
- **只广播不理解业务**: 总线不解析会话/端口语义, 只做帧归一化 + 分发; 过滤逻辑在各消费方。

### 1.2 设计原则

- **`opencode -sse-> service -event-> extensions`**: SSE 连接只由 service 层持有; extensions 不直接 `new EventSource`, 只订阅进程内事件。
- **单一事实源**: baseUrl 走 `infra/url` 的 `appBaseUrl()`, URL 走 `secureUrl()`; 总线不自行拼接/猜测来源。
- **引用计数懒连接**: 无订阅者时不保持连接 (沿用 ports 现有 `ensureSse/closeSse` 语义), 避免空闲 SSE; 再次订阅自动重建。
- **坏帧与重连容错**: 单帧 `JSON.parse` 失败静默丢弃; `onerror` 依赖浏览器 EventSource 自动重连, 不手写重连定时器。
- **消费方逻辑不动**: 总线只替换事件"来源", 各拓展的业务处理 (chat 大 switch / ports 缓存更新 / ask 文本累积) 原样保留。

### 1.3 核心链路

```
[opencode 服务端]
  会话事件 (message.part.delta / message.part.updated / session.idle / session.status ...)
  端口事件 (ports.detected / ports.closed, 信封 directory:"global")
        ↓ EventV2Bridge / GlobalBus.emit("event", { directory, payload })
[GET /global/event SSE]   ← 全局总线, 不按 workspace 路由
        ↓ 唯一一条 EventSource (service/event/eventBus.ts, 引用计数)
        ↓ 帧归一化
[service 消息总线]  进程内回调广播
        ├─ onEvent(cb)              全量帧 (chat: session.status/idle 全局 busy 对账)
        ├─ onEventType(types, cb)   按 type 过滤 (ports)
        └─ onSessionEvent(sid, cb)  按 properties.sessionID 过滤 (ask)
              ↓
[extensions] 端口面板 / 对话面板 / 提问命令 各自消费
```

**事件总线 API** (`sumi/src/service/event/eventBus.ts`, 框架无关单例):

```ts
export interface NormalizedEvent {
  type: string;                     // payload.type
  properties: Record<string, any>;  // payload.properties || payload.data
  directory?: string;               // 总线信封 directory (会话=工作区绝对路径, 端口="global")
  raw: any;                         // 原始帧 (调试用)
}
type Unsub = () => void;

// 全量订阅 (每一帧都回调)
export function onEvent(cb: (ev: NormalizedEvent) => void): Unsub;
// 按事件 type 订阅 (单个或多个)
export function onEventType(types: string | string[], cb: (ev: NormalizedEvent) => void): Unsub;
// 按会话 ID 订阅 (匹配 properties.sessionID)
export function onSessionEvent(sessionID: string, cb: (ev: NormalizedEvent) => void): Unsub;
```

**帧归一化规则**:
- 原始帧 `raw`; 总线信封取 `raw.payload` (V1 `/global/event` 包装) 或裸帧 `raw` 本身 (兜底)。
- `type = envelope.type`; `properties = envelope.properties || envelope.data || {}`; `directory = raw.directory`。
- `type` 或 `properties` 缺失 → 丢弃该帧。

**引用计数**:
- 每个 `on*` 订阅计数 +1 并 `ensure()` (计数 0→1 时 `new EventSource(secureUrl(base + '/global/event'))`)。
- 返回的 `unsub()` 计数 -1; 归 0 时 `es.close()` 并置空, 下次订阅重建。
- `es.onmessage` 统一解析后 fan-out 给所有订阅者; `es.onerror` 不处理 (浏览器自动重连)。

**不并入**: fs watcher (`service/filesystem/provider.ts` 用 `/api/fs/watch?directory=`, per-location, 事件 path 为 workspace 相对路径 + 200ms 防抖), 语义与全局总线不同, 保持独立。

## 2. 验收标准

### 2.1 单条 SSE

1. 完整使用流程 (开对话面板 + 开端口面板 + 触发一次提问命令) 后, DevTools Network 中 `/global/event` **只有一条**连接。
2. ask 触发期间**不出现** `/api/event` 连接 (ask 不再自建 SSE)。
3. 全部消费方卸载且无进行中提问时, 该 SSE 关闭 (引用计数归 0); 再次使用自动重建。

### 2.2 订阅与分发

1. `onEventType('ports.detected', cb)` 只在端口检测事件时回调; 会话事件不触发。
2. `onSessionEvent('<sid>', cb)` 只在 `properties.sessionID === '<sid>'` 的帧回调; 其他会话事件不触发。
3. `onEvent(cb)` 收到所有有效帧 (含 `directory:"global"` 的端口事件与带工作区目录的会话事件)。
4. 同一帧多个订阅者都收到 (fan-out 不丢、不串)。

### 2.3 帧归一化

1. 会话事件帧 (`{directory, payload:{type, properties}}`) 归一化后 `type`/`properties`/`directory` 正确。
2. 裸帧 / `data` 兜底形态也能解析 (`properties = properties || data`)。
3. 非法 JSON 帧静默丢弃, 不抛未捕获异常, 不影响后续帧。

### 2.4 容错

1. 网络抖动 EventSource 自动重连, 重连后订阅者无需重新注册 (回调仍在)。
2. `appBaseUrl()` 缺失 (opencode 未起) 时调用 `on*` 不抛未捕获异常 (订阅登记仍成功, 待 baseUrl 可用后重建)。
3. 总线模块可被 DI service / 纯函数 / React 组件三种环境直接 import, 无 DI 容器依赖。
